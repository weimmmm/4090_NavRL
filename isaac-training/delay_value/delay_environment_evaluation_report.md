# 无人机延时训练环境与评估报告

> 历史评估报告：以下参数和结果属于 2026-09-16 的两段延时版本，
> 不代表当前仅有 2–4 ms command→controller 延时的代码。当前配置见 README。

更新时间：2026-09-16

本文档介绍当前 `training_delay` 无人机训练环境的物理时钟、两段延时、动作队列、策略观测与奖励，并记录 `checkpoint_200.pt` 在精确延时特征和连续亚 tick 特征错配下的 1024 场景评估结果。

| 项目 | 当前设置 |

| 并行训练环境 | 2048 |
| 物理步长 | 2 ms，500 Hz |
| Actor 决策周期 | 100 ms，10 Hz |

## 2. 两段延时与动作队列

当前环境包含两段真实生效的延时。

### 2.1 第一段：odom 观测延时

- 每个 100 ms Actor 边界为各环境独立采样 46、48、50、52 或 54 ms。
- 环境在相应的历史物理 tick 捕获无人机状态快照。
- Actor 使用延迟快照中的位置和速度计算目标相对位置、速度以及动态障碍物相对状态。
- LiDAR 使用当前物理状态，不额外加入人工延时。
- reset 后的第一份观测没有可用历史快照，因此 odom 年龄为 0；之后进入正常随机范围。

### 2.2 第二段：command 传输延时

- Actor 每 100 ms输出一次三维速度命令。
- 连续 Weibull 样本在开区间 (60, 160) ms内生成，并向上量化到2 ms物理tick，因此真实释放范围是62–160 ms。
- 命令携带生成它时所使用的 odom 年龄，一起进入每环境独立的两槽 FIFO。
- FIFO 每2 ms检查一次到期命令，只允许从队首释放，后来的命令不能越过更早的命令。
- 低层速度控制器每2 ms持续执行当前已经生效的速度命令。

一次动作的总延时定义为：

```text
total_delay = 生成动作时使用的 odom 年龄 + 动作在 FIFO 中的实际等待年龄
```

由于 command 延时可能超过100 ms，相邻Actor命令可以同时处于传输过程中；两槽FIFO正是为这种重叠设计的。

### 2.3 时序示意

```text
历史物理状态 ── odom延时 ──> Actor观测
                                  │
                                  ├─ 每100 ms推理一次
                                  ▼
                              速度命令
                                  │
                         command延时 + 两槽FIFO
                                  ▼
                    每2 ms检查并更新生效命令
                                  │
                                  ▼
                    低层控制器每2 ms推进物理
```

## 3. 策略观测输入

策略接收四类输入：19维状态、LiDAR、动态障碍物特征和方向向量。

### 3.1 19维状态

| 索引 | 维度 | 内容 |
| --- | ---: | --- |
| 0–2 | 3 | 目标坐标系中的单位目标方向，使用延迟 odom 位置计算 |
| 3 | 1 | 水平目标距离 |
| 4 | 1 | 垂直目标距离 |
| 5–7 | 3 | 目标坐标系中的无人机速度，来自延迟 odom |
| 8–10 | 3 | 当前已经生效的 command，转换到目标坐标系 |
| 11–13 | 3 | FIFO 队首等待中的下一条 command，转换到目标坐标系 |
| 14 | 1 | 当前 odom 年龄 ÷ 54 ms |
| 15 | 1 | 当前生效 command 的实际传输延时 ÷ 160 ms |
| 16 | 1 | 当前生效 command 的总延时 ÷ 214 ms |
| 17 | 1 | FIFO 队首 command 已等待时间 ÷ 160 ms |
| 18 | 1 | 当前队列深度 ÷ 2 |

五个延时/队列特征均限制在 [0, 1]。策略不会看到尚未采样的未来延时。

### 3.2 LiDAR

- 输入形状为 `1 × 36 × 4`。
- 水平分辨率10°，覆盖360°；垂直方向4束，视场为 -10°至20°。
- 最大探测距离4 m。
- LiDAR经过CNN编码为128维特征。
- 当前实现没有人为添加LiDAR延时。

### 3.3 动态障碍物

策略接收最近5个动态障碍物，每个障碍物10维：

- 目标坐标系中的单位相对方向：3维；
- 水平距离和垂直距离：2维；
- 目标坐标系中的障碍物速度：3维；
- 宽度类别和高度类别：2维。

无人机与障碍物的相对位置使用延迟 odom 计算，动态障碍物特征经MLP编码为64维。

### 3.4 方向向量与网络输入

`direction` 是一个 `1 × 3` 目标方向向量，主要用于将Actor输出从目标坐标系转换回世界坐标系，不直接拼入策略特征提取器。网络将128维LiDAR特征、19维状态和64维动态障碍物特征拼接，再通过256维MLP送入Actor和Critic。

## 4. 奖励与训练统计

当前奖励的主要目标是让策略真实接近目标、提前减速并最终停在目标内：

- 距离进展奖励：`2.0 ×（transition开始距离 - 最后有效状态距离）`；
- 目标驻留：距离小于0.5 m时，每个100 ms transition获得 `+0.5`；
- 近目标减速：2 m内逐渐增加 `-0.2 × near_goal_weight × speed²`；
- 保留静态/动态障碍物安全、生存、高度和速度平滑项；
- 到达目标不终止，碰撞或飞行高度越界才终止，35.2 s到期则截断。

关键指标定义：

- `reach_goal`：回合最后有效状态是否位于目标0.5 m内；
- `reached_ever`：回合中是否曾进入目标0.5 m范围；
- `goal_hold`：最后有效状态是否同时满足距离小于0.5 m、速度小于0.25 m/s；
- `min_goal_distance`：整个回合中的最小目标距离；
- `collision`：是否发生静态或动态障碍物碰撞。

PPO按100 ms高层transition计算一次折扣与GAE，使用 `gamma=0.99`、`lambda=0.95`。

最近一次续训在新运行内执行到第238次更新、15,663,104帧后停止；最后保存的是第200次更新权重。续训日志在第230次更新时记录：`reach_goal=67.90%`、最近5次均值68.52%、`reached_ever=68.87%`、碰撞率2.43%。本报告的两次评估都使用第200次更新权重：

## 5. 两次评估设置

两组评估共享以下条件：

- 1024个固定场景，场景由训练分布生成；
- 350个静态障碍物、80个动态障碍物；
- 物理步2 ms、Actor周期100 ms、回合35.2 s；
- odom和command两段随机延时从第一步启用；
- 两槽FIFO；
- 同一个 `checkpoint_200.pt`；
- `seed=12345`；
- 使用Actor分布的确定性均值动作；
- 不录制视频。

两组唯一有意差异如下。

| 评估组 | 真实物理延时 | 策略看到的延时特征 |
| --- | --- | --- |
| 精确特征基线 | 2 ms tick上的真实odom与command延时 | 与真实生效值一致 |
| 连续±1 ms错配 | 与基线完全相同 | odom和command各加入连续、均匀、有界的±1 ms误差 |

错配评估中，`total_delay`由带误差的odom与command分量重新组成，因此最大可能误差为2 ms；pending command age和队列深度保持精确。第三路独立随机数流只生成特征误差，不改变真实的odom或command延时序列。

这项实验测试的是**延时特征错配**，不是将物理执行改成亚2 ms。真实odom快照、FIFO释放和动力学推进仍严格发生在2 ms tick上。

## 7. 评估结果对比

| 指标 | 精确特征 | ±1 ms错配 | 变化 |
| --- | ---: | ---: | ---: |
| `reach_goal` | 70.90%（726/1024） | 70.80%（725/1024） | -0.10个百分点 |
| `reached_ever` | 70.90% | 70.80% | -0.10个百分点 |
| `goal_hold` | 68.95%（706/1024） | 68.95%（706/1024） | 0 |
| `collision` | 3.61%（37/1024） | 1.07%（11/1024） | -2.54个百分点 |
| `min_goal_distance` | 7.328 m | 7.772 m | +0.444 m |
| 到时截断率 | 96.39% | 98.93% | +2.54个百分点 |

到达目标本身不会终止回合，因此“到时截断”通常表示无人机安全运行到35.2 s，不等于失败。精确组和错配组的 `reached_ever` 与最终 `reach_goal` 相同，说明这两次评估中没有出现“曾到达但最终离开目标区域”的场景。

`reach_goal`只变化了1/1024个场景，`goal_hold`完全相同，说明当前策略对±1 ms的亚tick延时特征误差不敏感。碰撞率差异不能直接解释为错配带来的改进：Isaac GPU物理、动态障碍物以及动作微小变化会放大轨迹分叉；历史上相同seed的精确评估也曾得到69.73%成功率和2.25%碰撞率，说明单次运行存在约1个百分点级成功率波动和更明显的碰撞率波动。

因此本次实验支持的结论是：

> 在真实物理延时与FIFO保持不变时，给策略输入的odom和command延时各加入连续±1 ms误差，没有造成可测的目标成功率下降。

该结论不代表更大的特征误差、错误的队列深度、或真正改变物理释放时刻也不会影响策略。
